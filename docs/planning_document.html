BAGIAN I: PRODUCT REQUIREMENT DOCUMENT (PRD)

1.1 Latar Belakang & Masalah UMKM

Mayoritas pelaku usaha mikro, kecil, dan menengah (UMKM) di Indonesia yang mengelola lebih dari satu cabang menghadapi kendala kritis:

  • Fragmentasi Data Transaksi: Operasional kasir masih terpisah-pisah, kasir mencatat di aplikasi offline atau kertas, menyebabkan rekap harian lambat dan rentan salah hitung.
  • Ketiadaan Data Pelanggan (CRM): Transaksi terjadi tanpa mengumpulkan kontak pelanggan. Pemilik tidak memiliki data siapa pelanggan setia, berapa rata-rata nilai transaksi (AOV), dan kapan mereka terakhir berbelanja.
  • Owner Mengalami Kebutaan Data Penjualan (Blind Monitoring): Pemilik toko harus menunggu laporan manual via chat WhatsApp tiap malam, menyulitkan mitigasi kecurangan uang kas dan pengambilan keputusan stok barang.

1.2 User Persona & Peran Pengguna

Persona Peran Kebutuhan Utama & Pain Point
Kasir (Cashier) Operasional kasir di toko Alur pencarian produk instan, hitung kembalian otomatis, cetak struk thermal cepat (< 5 detik), dan tidak boleh bingung saat antrean panjang.
Kepala Cabang (Manager) Supervisi outlet harian Buka & tutup register kas (modal awal vs uang fisik akhir shift), pantau pergerakan stok harian, dan audit transaksi kasir.
Pemilik Usaha (Owner) Pengambil keputusan bisnis Live dashboard penjualan real-time di smartphone, komparasi performa cabang, laporan laba kotor, dan retensi pelanggan (CRM).
SuperAdmin SaaS Pengelola platform cloud Manajemen onboarding tenant baru, pemantauan masa aktif langganan, dan stabilitas server.

1.3 Ruang Lingkup Produk (In-Scope vs Out-of-Scope)

Prinsip MVP: Fokus pada kecepatan, stabilitas multi-tenancy, dan kehandalan transaksi kasir. Fitur integrasi pihak ketiga yang berat ditunda setelah traksi awal terbukti.
  • In-Scope (Rilis 14 Hari):
    • Terminal POS responsif (tablet & laptop), pencarian produk cepat, barcode scanner support.
    • Kalkulasi diskon, PPN, split payment dasar (Cash, QRIS Statis, Transfer Bank).
    • Cetak struk thermal 58mm/80mm ESC/POS dan kirim struk WhatsApp Web link.
    • Database CRM berbasis No. WhatsApp, poin loyalitas, riwayat transaksi belanja pelanggan.
    • Dashboard live feed transaksi real-time (Laravel Reverb) untuk owner.
    • Pencatatan shift kasir (opening cash, cash drop, closing reconciliation).
  • Out-of-Scope (Fase Pasca-MVP):
    • Integrasi Payment Gateway otomatis (Midtrans/Xendit) — di MVP kasir cukup klik "QRIS / Lunas".
    • Manajemen Bill of Materials (resep bahan mentah F&B kompleks).
    • Integrasi hardware timbangan digital otomatis.

BAGIAN II: PRODUCT SPECIFICATION DOCUMENT (PSD)

2.1 Arsitektur Sistem & Komponen Teknis

Sistem dirancang dengan pola Modular Monolith menggunakan Laravel 11 untuk memaksimalkan efisiensi solo development tanpa beban maintenance microservices:

  • Backend Core: Laravel 11 (PHP 8.2+) dengan arsitektur Domain-Driven Modul (POS, CRM, Analytics, Tenancy).
  • Database: PostgreSQL 16 dengan isolasi tenant_id otomatis via Eloquent Global Scope.
  • WebSockets: Laravel Reverb untuk transmisi event transaksi real-time dari kasir ke dashboard owner.
  • Caching & Queue: Redis untuk queue pembuatan laporan, sinkronisasi poin, dan cache katalog produk.

2.2 Strategi Multi-Tenancy (PostgreSQL)

Menggunakan pendekatan Single Database, Shared Schema dengan Discriminator Column (tenant_id).

// app/Scopes/TenantScope.php
namespace App\Scopes;

use Illuminate\Database\Eloquent\Builder;
use Illuminate\Database\Eloquent\Model;
use Illuminate\Database\Eloquent\Scope;

class TenantScope implements Scope
{
    public function apply(Builder $builder, Model $model)
    {
        if (auth()->check() && auth()->user()->tenant_id) {
            $builder->where($model->getTable() . '.tenant_id', auth()->user()->tenant_id);
        }
    }
}

Setiap entitas bisnis diisolasi secara transparan. Tidak ada kasir atau owner dari toko A yang dapat melihat data transaksi dari toko B.

2.3 Skema Database Utama (PostgreSQL DDL)

Tabel: tenants, outlets, users

CREATE TABLE tenants (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name VARCHAR(255) NOT NULL,
    subdomain VARCHAR(100) UNIQUE NOT NULL,
    phone VARCHAR(50),
    is_active BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE outlets (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
    name VARCHAR(255) NOT NULL,
    address TEXT,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id UUID REFERENCES tenants(id) ON DELETE CASCADE,
    outlet_id UUID REFERENCES outlets(id) ON DELETE SET NULL,
    name VARCHAR(255) NOT NULL,
    email VARCHAR(255) UNIQUE NOT NULL,
    password VARCHAR(255) NOT NULL,
    role VARCHAR(50) NOT NULL -- 'superadmin', 'owner', 'manager', 'cashier'
);

Tabel: customers (CRM), orders, dan order_items

CREATE TABLE customers (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
    phone VARCHAR(30) NOT NULL, -- Nomor WhatsApp unik per tenant
    name VARCHAR(255),
    loyalty_points INTEGER DEFAULT 0,
    total_spend NUMERIC(15, 2) DEFAULT 0.00,
    visit_count INTEGER DEFAULT 0,
    last_visit_at TIMESTAMP WITH TIME ZONE,
    CONSTRAINT unique_tenant_customer UNIQUE (tenant_id, phone)
);

CREATE TABLE orders (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
    outlet_id UUID NOT NULL REFERENCES outlets(id),
    cashier_id UUID NOT NULL REFERENCES users(id),
    customer_id UUID REFERENCES customers(id),
    invoice_number VARCHAR(100) NOT NULL,
    subtotal NUMERIC(12, 2) NOT NULL,
    discount_amount NUMERIC(12, 2) DEFAULT 0.00,
    tax_amount NUMERIC(12, 2) DEFAULT 0.00,
    grand_total NUMERIC(12, 2) NOT NULL,
    points_earned INTEGER DEFAULT 0,
    points_redeemed INTEGER DEFAULT 0,
    payment_method VARCHAR(50) NOT NULL, -- 'cash', 'qris', 'bank_transfer'
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT unique_tenant_invoice UNIQUE (tenant_id, invoice_number)
);

CREATE TABLE order_items (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    order_id UUID NOT NULL REFERENCES orders(id) ON DELETE CASCADE,
    product_id UUID NOT NULL REFERENCES products(id),
    quantity INTEGER NOT NULL CHECK (quantity > 0),
    unit_cost_price NUMERIC(12, 2) NOT NULL,
    unit_selling_price NUMERIC(12, 2) NOT NULL,
    subtotal NUMERIC(12, 2) NOT NULL
);

2.4 Real-time Event Architecture (Laravel Reverb)

Alur transmisi data saat transaksi terjadi:

  1. Kasir menekan tombol Bayar & Selesai di terminal POS.
  2. Sistem mengeksekusi DB transaction: kurangi stok, tambah poin pelanggan, simpan order.
  3. Sistem menembakkan event: OrderCompletedEvent::dispatch($order).
  4. Laravel Reverb menyiarkan event ke channel pribadi: private-tenant.{tenantId}.live-sales.
  5. Layar Owner di mana pun berada langsung menampilkan popup suara & meng-update total pendapatan detik itu juga.
